# v1.56.0 - Bug Fixes & Logging Improvements

**Release Date**: January 7, 2026

## 🐛 Bug Fixes

### REC Indicator Position
- **Fixed**: REC indicator appearing in wrong position (bottom-left outside border during drag, top-left during resize)
- **Root Cause**: `show()` method was missing `region_width` parameter for proper coordinate calculation
- **Solution**: 
  - Added `region_width` parameter to `show()` method signature
  - Updated coordinate calculation: `x + region_width - width - border_width - 5` (now correctly positions in top-right)
  - Fixed `update_position()` call to pass `border_width` instead of `height`
  - Updated trait and all implementations

### Preview Border Crash
- **Fixed**: Preview border disappearing and app crashing when moved
- **Root Cause**: Production callbacks (capture engine update) and REC operations being called in preview mode where these systems don't exist
- **Solution**: Added `PREVIEW_MODE` checks before:
  - Calling `BORDER_INTERACTION_COMPLETE_CALLBACK` in `mouseUp`
  - REC `hide()` calls in `mouseDown` (drag and resize)
  - REC `update_position()` call in `mouseDragged`
  - REC `show()` call in `mouseUp`

### Preview Border Interaction Loss
- **Fixed**: Preview border losing all interaction after first drag
- **Root Cause**: `mouseUp` was setting `setIgnoresMouseEvents: YES` for both preview and capture modes
- **Solution**: Added preview mode check - only disable mouse events in capture mode, keep enabled in preview mode

### Preview Border Coordinate Issues
- **Fixed**: Preview border jumping to random positions during drag/resize
- **Root Cause**: Both Cocoa's native `setMovableByWindowBackground: YES` and manual drag implementation were active simultaneously, causing double movement
- **Solution**: 
  - Set `setMovableByWindowBackground: NO` in `set_preview_mode()`
  - Use only manual drag implementation for consistency

### Preview Border Lag
- **Fixed**: Laggy/stuttering movement when dragging preview border
- **Root Cause**: Heavy operations being performed on every `mouseDragged` event even in preview mode
- **Solution**: Skip unnecessary operations in preview mode:
  - `displayIfNeeded` and `flushWindow` (only needed for screen sharing in capture mode)
  - `invalidateCursorRectsForView` (cursor doesn't change in preview)
  - `BORDER_RECT_CACHE` update (no capture engine in preview)
  - REC position updates (no REC in preview)

## 📝 Logging Improvements

### Visual Log Markers
- **Added**: Visual markers in log files for easy identification of startup information
- **Format**: 
  ```

  *                        RUSTFRAME STARTUP                            *
  ***********************************************************************
  ```
- **Sections**:
  - Application startup with version, platform, log level

- **Added**: Comprehensive system information at startup (debug level):
  - Operating system and architecture
  - Display configuration (scale factor, width/height in points and pixels)
  - Active settings (capture method, FPS, border, cursor, REC indicator settings)
  - Active profile name
  - Log configuration (level, file output, retention days)

### Preview Mode Log Cleanup
- **Fixed**: Excessive "Mouse dragged delta calculation" trace logs during preview border movement
- **Solution**: Added preview mode check - only log drag calculations in capture mode

### Coordinate System Fix
Previous (incorrect):
```rust
let pos_x = x - width - border_width - 5; // Would place at LEFT side
```

Current (correct):
```rust
let pos_x = x + region_width - width - border_width - 5; // Places at RIGHT side
```

### Preview vs Capture Mode Separation
The key architectural fix was properly separating preview and capture mode code paths:

**Preview Mode**:
- No capture engine exists
- No REC indicator exists
- No callback to update capture region
- Optimized for UI interaction only

**Capture Mode**:
- Full capture engine running
- REC indicator active
- Callbacks update capture region
- All screen sharing optimizations active
